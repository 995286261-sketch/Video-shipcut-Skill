# Mimosa 钩子误拦只读 Bash —— 反馈稿 v0.1

> 性质：给插件上游的反馈素材草稿。2026-10-10 banshee-001 测后批 ⑬（乙案，用户拍板）落档。
> **是否发送、发到哪里、何时发送由用户决定；本稿只是"把三次误拦写清楚备用"，不代表已发生任何上报。**

## 环境

- ZCode 桌面端 + 官方插件 `mimosa` 1.0.3（PreToolUse hooks：`scan-hook.mjs` 匹配 Edit|Write|MultiEdit，`git-gate-hook.mjs` 匹配 Bash）。
- 项目为本地视频流水线仓库，日常含大量"复制合同/产物到留档目录、再跑只读校验脚本"的编排动作。

## 现象（三次实录，均为只读/写目标在仓库外的命令被拒）

拦截提示原文：

> Bash 直接写源码/安全配置会绕过 Write/Edit 安全扫描。请改用 Write/Edit 提交同一内容；这样 PreToolUse 才能检查候选代码，并在有高危问题时给出可修复反馈。

1. `cp <仓库内合同文件> <仓库外留档目录> && python3 <skill 内校验脚本> --plan …`
   —— 写入目标是留档目录里的新文件；`skill/` 路径只出现在**读位置**（复制源 / 脚本自身路径）。被拒。
2. `cp … && grep -n <关键词> skill/<某脚本>.py`
   —— 后半段纯只读 grep。被拒。
3. 2026-10-10 彩排：`mkdir <WorkSpace 彩排目录> && cp <交付包副本> … && python3 skill/loudness-expert/scripts/loud_verify.py --bundle-copy …`
   —— 写目标全部在仓库外 WorkSpace；因命令行同时含 `cp` 与 `skill/` 路径被拒。拆成两条后即放行。

三次共同模式：**判定疑似只看"命令行中是否同框出现 复制/重定向 类 token 与 源码目录路径"，未解析实际写目标位置**。

## 期望

- 判定应基于**写目标**：重定向/复制目的地/输出参数的实际路径是否落在受保护源码面内；源码路径出现在读位置（复制源、脚本自身、grep 目标）不应触发。
- 保持现有"真写源码必须走 Write/Edit 扫描"的红线不变——本反馈不主张放宽，只主张**别误伤读位置**。

## 本地侧态度（如实声明）

- 钩子本体为插件受保护资产（protected asset pack），判定逻辑本地不可见亦未尝试修改；本项目从未以任何方式绕过守卫写源码——所有源码/配置写入一律走 Write/Edit 正规通道。
- 绕行纪律已成文：编排类长命令避免 `cp` 与源码路径同框，拆分为多条短命令执行。

## 复现要点

任何 `cp <仓库内文件> <仓库外目录> && python3 <仓库内脚本> …` 组合即可复现；拆分后逐条执行均放行。
