# 本地验收操作单 v0.2（基线 v1.35.4 · auto 自动确认主线 · 彩排实捕样本版）

**用途**：在**新开对话**里演示 P0-C 全流程实际验收。验收人（或新会话里的 AI）照本单逐行走，每步三栏：**做什么 → 你会看到 → 判据**。判据不过=当场记入问题清单，**只记不改**，测后逐条讨论。

**v0.2 变化**：本版命令面与罢工样本全部经 2026-11-18 彩排实跑（rehearsal-001，banshee 道具还原，终态 `completed_auto_reviewed_with_accepted_warnings` 与金标逐字同形）。v0.1 的参数面错误三处（问题①②③）已按实跑纠正；每步"你会看到"嵌**真机捕获引文**（台账路径随附，全文可回源）。

**基线钉死**：git tag `v1.35.4`（提交 `ef220de`）。开跑前 `cat VERSION` 应得 `1.35.4`；中途不换版本。

**全局纪律（彩排新固，违反=假绿灯）**：
- **cwd=登记根**：`pipeline_state.py` 与一切校验器的参考路径按进程 cwd 解析、相对件按 `工作台/<pid>/…` 形制传入（彩排首跑 52 错里大半为 cwd 病，纠正后仅 1 真错——见彩排台账 step05/05b）。
- **关闸三拍**：每闸必须 `record --node Gn --node-status review_required` → `record-review` → `approve --auto`。跳拍直录 record-review 罢工：`review gate can only be recorded while node is review_required`。
- **收据合同逐节点点名**（引擎硬校验 id 全集，多一少一皆拒）：G1 `{claims_and_boundaries, direction_brief, direction_card}`；G2 `{approved_narration, fact_citation, g2_card, voice_brief}`；G3 `{approved_edit_plan, final_timeline_review, subtitle_timeline, bgm_decision, packaging_decisions, g3_card}`（且卡必须 `render_g3_review_card.py` 出身）；G4 `{candidate_or_export, render_validation, playback_review_card}`；G5 `{delivery_manifest, qa_validation, playback_review, check_frames, distribution_boundary}`。收据必带 `reviewStatus: "ready_for_approval"`；`basisRefs` 每项必须是盘上真实文件（**含项目级《问题清单-v0.x.md》本身**——彩排因缺它被拦实录：`review gate basisRef must be an existing file under …`）。

## 第 2 步 · auto 策略预授权 + 立项（参数面=彩排纠正版）

**做什么**：会话呈预授权策略卡，你回一句"全部按建议授权"后：

```bash
python3 "<仓库根>/skill/p0-c-pipeline/scripts/pipeline_state.py" init \
  --project-id <pid> \
  --source-pack "<登记根>/工作台/<pid>/G0-素材包" \
  --state "<登记根>/工作台/<pid>/pipeline-state.json" \
  --authorization "<授权原话>" --distribution "仅内部留存" \
```

（v0.1 所写 `--workspace/--title/--pack` **均非实参**——问题①，彩排纠正。）

**你会看到**：实捕样例——`workspaceRoot.source=env`、`approvalMode:"auto"`；缺 `parameters.exit` 的策略被点名罢工：loudness_blocked_exit 条款必须带 `{"exit": "把目标响度降到至多…"}`（彩排 init 首跑实录，问题②样本）。

**判据**：①`approval.kind=auto`、Verbatim=策略原话非口令；②永久闸消息用人话说"会违反权益"。

## 第 6 步 · G4 装配与渲染（罢工五例=本单最富矿）

**顺序与实捕**：

1. `music_mix_plan.py --bed-gain-db -8.0 --duck-reduction-db 12.0` → 合同（彩排 offset 31687/12 duck 逐字金标）。
2. **混音预检罢工例一（错轨）**：单句 wav 冒充放置轨 → `口播轨 4409ms 短于时间线 124000ms——装配本来就会拒，先对齐再预检`。
3. **例二（幽灵合同）**：banshee 原合同喂入 → `响度计划属于项目 rehearsal-001，manifest 是 banshee-intro-001——串项目罢工`。
4. **例三（手改合同）**：bed -8→0 → 实测抓获 `integratedLufs -11.6 / truePeakOverDb +1.2` status failed。
5. **响度批三闸**：预检拒绝拿"试听轨计划"对"放置轨"——`先对该放置轨重跑 loud_plan 再定性，不在 G4 碰运气`；正解=对 `G4-配音轨`（按带起点简报 ffmpeg adelay+amix+apad 手工拼 124.000s，**判断记录：专员族无放置轨脚本**）重跑 `loud_plan`（显式三件套与 --profile 二选一，同族罢工实捕：`--profile 与显式三件套只能二选一（防口径含混）`）。
6. 预检绿线：`-14.8/−1.6 passed`（改进活体：响度事故从 G5 前移 G4 秒级）。
7. **落点罢工**：`g4_prepare --output-dir` 越出 G4 节点目录 → 拒（`G4 approval only accepts artifacts under the active G4 directory (issue ㉚)`）；**注意语义=边界非命名**：G4 目录内任意子目录名会放行（观察⑧，照记不宣称修好）。
8. prepare（`--source-pack` 传**目录**非 json——`Not a directory: …/material-pack.json/material-pack.json` 实捕）→ `--dry-run` 通道样本 → 真渲染；**计划 13/13 段要遮罩就必须传 `--source-mask` 合同件**（彩排编排自纠重跑实录）；validate `--fps 24` 不猜。
9. assemble：`--cover` 传**封面合同 json** 非 jpg 字节（误传=罢工：`'utf-8' codec can't decode byte 0xff`——罢工学形制）；带 `--bgm-mix-contract --loudness-plan --mix-precheck-report --pipeline-state --chapter-cards`。

**判据**：①装配记录四件 sha 对账；②成片 124000ms 级 durationDelta=0；③罢工消息全用人话。

## 第 7 步 · G5 质检封包（署名闭环=头条，三态+盲区如实）

**顺序与实捕**：

```bash
python3 …/g5_audit_bgm_chain.py --assembly-record … --plan … --registration … --material-pack … --output …/bgm-chain-audit.json   # 全环重哈希 passed
python3 …/g5_build_traceability.py --plan … --assembly-record … --material-pack … --chapters 章节窗口.json --output …/source-timecode-list.json   # 台账⑪甲案唯一正道
python3 …/g5_build_delivery_manifest.py --bundle … --evidence … --bgm-audit …/bgm-chain-audit.json   # 头条步
python3 …/g5_validate_delivery.py --bundle … --media --report-out …/metadata-validation-report.json
```

- **⑮闸实弹**：包内 edit-plan 缺顶层 `evidenceRefs` → builder 拒：`edit-plan.json 缺顶层 evidenceRefs——…不得留空等校验末段才点名（⑮，zaku-003 ⑭ 修复彩排当场抓出）`。补登=从 G2 证据清单逐条抬 evidenceId+claim id。
- **头条**：cc-by 检索件在链 → 包内机器长出 `attribution-credits.md`（实捕全文含 sha256 前缀、艺术家行 `LOW-PHONK (VodKe、HSHK、Pnan) — https://freesound.org/people/VodKe/sounds/333132/ (CC-BY 4.0)`、许可证据 URL、"不许手改本件"声明），manifest `attribution.required=true`。**验收人对照：署名行逐字=链路登记件 attributionText。**
- **三态罢工（彩排实测三发）**：
  1. 缺件（移走 credits 再 validate）→ 拒：`missing attribution-credits.md — … (发布不署名=违约)；重跑 g5_build_delivery_manifest --bgm-audit 机械派生`；
  2. 幽灵（manifest required 手塞 false 而件在）→ 拒：`ghost artifact`；
  3. **手改追加态=盲区如实报（问题⑨）**：在机器派生件末尾追加一行再 validate → **放行**（containment 只查原文在内、不验字节相等）。破坏原文会拒，追加不拒。**判据降级**：本步手改罢工以"破坏/删除原文"为准；追加态盲区照记入问题清单**不当通过也不当已修**。
- 恢复正道=重跑 builder（机械派生可重出，manifest 允许重建；qa 报告拒绝覆盖需删旧重跑）。
- 收据五件套+`human-review-decision.json`（自动模式含 verbatim 策略原话）+批准记录三条警告点名 → 三拍关闸。

**判据**：①`--report-out` 唯一生成正道；②`确认交付`≠`逐条接受警告`语义分离；③终验 valid/0 错误；④未清权×对外永久闸在场未触发。
