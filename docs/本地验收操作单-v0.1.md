# 本地验收操作单 v0.1（基线 v1.35.4 · auto 自动确认主线）

**用途**：在**新开对话**里演示 P0-C 全流程实际验收。验收人（或新会话里的 AI）照本单逐行走，每步三栏：**做什么 → 你会看到 → 判据**。判据不过=当场记入问题清单（格式见末节），**只记不改**，测后逐条讨论。

**基线钉死**：git tag `v1.35.4`（提交 `ef220de`）。开跑前 `cat VERSION` 应得 `1.35.4`；中途不换版本。

**形制出处**：connector 侧《评审验收操作单》同款（命令必须真跑过、罢工步失败=通过、末列"哪些不该签"）。与《验收-录制脚本-v0.1》的分工：那是给人录像的剧本（human 主线），这张是给新会话照做的验收单（auto 主线）。

**判据**：①开场白里没有"上次我们做过…"类记忆转述；②选址或九问走的是预设卡模板不是即兴散文；③工作目录=机器现有登记根（本机 10-30 已登记，正常应**不再弹卡**直接进九问——弹了=选址记录丢了，记问题）。

## 第 1 步 · G0 素材入场（九问一次问完）

**做什么**：按九问卡逐题回答（受众用途/素材/去向=建议选**内部测试**/是否配音/BGM 意向等）。素材须是你亲供的授权明确件（自拍或无版权；≤3 分钟单一主体最省时）。

**你会看到**：`工作台/<projectId>/G0-素材包/` 建目录树；register 对音频跑解码探针、对缺项点名指路；validate 出 `incomplete`/`passed`；最后 G0 回显卡+开工单结论。

**罢工步（失败=通过）**：故意把一个音频素材不带授权登记件放进 07 → register 应回 `incomplete` 且点名"先跑 music_register_candidate"；补齐后过。

**判据**：①九问一张卡问完（冲突才插第二卡）；②每个缺口报错自带下一步命令；③源媒体目录只读、产物全部落在登记根下。

## 第 2 步 · auto 策略预授权 + 立项

**做什么**：G0 关单前后，会话呈**预授权策略卡**（七类：材料充分性/低风险选择/质量微调/水印台标类窄范围警告接受/……全表以卡面为准）。你回一句：

> 全部按建议授权

会话随即：

```bash
python3 skill/p0-c-pipeline/scripts/pipeline_state.py init \
  --workspace "<登记根>" --project-id <pid> --title "<片名>" --pack <素材包目录> \
  --approval-mode auto --auto-policy <auto-policy.json 落盘路径>
```

**你会看到**：`pipeline-state.json` 内 `approvalMode: "auto"`；auto-policy JSON 含策略七类与你的逐字原话。

**罢工步（失败=通过，永久闸两例）**：
1. `init --approval-mode auto` 不带 `--auto-policy` → 当场拒："无策略不自动"；
2. 素材包去向选**对外发布** + BGM 用未清权件 → 无论哪种模式，关单**永久 fail-stop**——这是"未清权×对外"端到端闸，**它必须炸，炸了才通过**。

**判据**：①绝不伪造人类口令——批准记录里 `approval.kind=auto`、`approvalSource=auto-policy`，`Verbatim` 存的是你授权策略的原话不是口令；②永久闸罢工消息用人话说清"会违反权益"。

## 第 3 步 · G1 方向+找乐（卡流式照出）

**做什么**：回答方向三问（受众用途复述/风格参照/音乐意向——口头一句即可，如"来点电子的"）。

**你会看到**：卡片**照常逐张流出**（auto 只换批准人不换交互）：检索词卡→候选歌卡（侵权横幅/未清权标签必显）→你一句即决的原话挑曲→登记→音乐初次分析产物齐。之后 `record-review` → `approve --auto` 关单，回显最终卡。

**罢工步（失败=通过）**：BGM 槽挂着 `libraryPending` 未清就试图翻 G2 → G2/G3 approve 硬拒（"槽不得靠口头清空"）。

**判据**：①找乐结果与方向同呈、G1 一锤盖两件事；②经验库查库先行（红绿灯列在场）；③门禁收据 basisHashes 冻结了被审文件指纹（R2 形状）。

## 第 4 步 · G2 证据与口播

**做什么**：挑叙事角度（单卡默认=推荐，点头即可）；对英文配音选音色（试听卡三选一：Samantha/Daniel/Karen）。

**你会看到**：事实清单（每句可点回证据文件）+口播稿+配音清单（逐句 wav+实测时长+sha）。auto 关单参数链：`approve --node G2 --auto --approved-narration-ref … --fact-citation-ref … --voice-brief-ref …`（缺一个引用就罢工，罢工消息点名缺哪个）。

**判据**：①素材里没有的事实它会说"无证据"而不是编；②ASR 回读自检结果如实标注（同音判读=人判通道不许写成机器通过）。

## 第 5 步 · G3 剪辑计划

**做什么**：等计划卡出。要转场就明说，不要就默认硬切。

**你会看到**：八列回显固定表+转场预览区+封面帧机抽+评审点名单；`validate_g3_plan` 的批量报错（故意写一段"希望出现 XX"式愿望句可当投毒罢工步：errors[] 一次报全、`mappingMode: sequence` 评审期就拒）。

**判据**：①每段 `observedVisuals` 来自三帧实验不是想象；②预览硬闸在场（缺试装预览=点名拒，唯一豁免=如实披露句）；③顶层 evidenceRefs/humanReviewPoints 齐（缺=builder 罢工，⑮闸）。

## 第 6 步 · G4 装配与渲染

**做什么**：`确认G4` 前挂机渲染（可离开）。

**罢工步（失败=通过，本步三例）**：
1. 混 BGM 不交预检报告就 assemble → 拒装点名 `--mix-precheck-report`（唯一豁免=如实披露 waiver）；
2. `g4_prepare --output-dir` 指到项目目录外 → 当场 `blocked`（落点闸，不等关单）；
3. 计划改动后拿旧预检报告再来 → 过期罢工（时间戳对账）。

**你会看到**：`g4_assemble` 装配记录带混音实测（ebur128 数字与预检对得上）；成片时长与批准计划分毫不差。

**判据**：①装配记录 mixPrecheck 块四件 sha 逐字对账；②产物只写 `工作台/<pid>/` 界内；③封面帧来自登记件机抽（coverProvenance 在场）。

## 第 7 步 · G5 质检与封包（含署名闭环首次验收镜头）

**做什么**：等机检跑完，看交付卡。

**你会看到**（本单最重要的一组新闸门——v1.35.4 署名闭环）：
```bash
python3 skill/media-qa-delivery/scripts/g5_audit_bgm_chain.py ...   # 15 环含 attributionRecorded
python3 skill/media-qa-delivery/scripts/g5_build_delivery_manifest.py \
  --bundle ... --evidence ... --bgm-audit g5-bgm-chain-audit.json --output ...
python3 skill/media-qa-delivery/scripts/g5_validate_delivery.py --bundle ... --media ... --report-out ...
```
- 若本次 BGM 是 **CC-BY 检索件**：包内自动长出 `attribution-credits.md`（机器派生），manifest `attribution` 块留账——**验收人点开对照：署名行逐字=链路里的 attributionText**。
- 若是 cleared 自有件：无义务=不冒署名件（幽灵件反证）。

**罢工步（失败=通过，三态拒）**：手改 `attribution-credits.md` 一个字节再跑 validate → 拒封点名"机器派生件，修链路重跑装配，不许手编"。

**判据**：①质检报告只有 `--report-out` 一条生成正道（generatedBy 出处行、每证据文件现算指纹）；②`确认交付` 与 `逐条接受警告` 语义分开（G5 卡上两行都有）；③封存包 `g5_validate` valid/0 错误。
