## 2. 概念小课（人话）

- **LUFS**：耳朵感知的"有多响"，随时间平均（integrated=整段平均）。行业标准算法 ITU-R BS.1770-4 / EBU R128。
- **dBFS / 真峰值 TP**：波形瞬时的"顶得多高"，与"听着多响"是两回事。TP 超 0 会削波爆音。
- **LRA**：响度的起伏范围（安静段到高潮段跨多大），不是响度本身。
- **一句话规则**：目标管"平均有多响"（LUFS），天花板管"会不会爆"（TP），起伏（LRA）只做参考不设闸。

## 3. 调研：开源世界有什么现成的

### 3.1 ffmpeg `loudnorm` 滤镜（我们已在用，但用法有坑）

官方文档（ffmpeg.org filters 8.97）核实：

- 支持单遍动态与**两遍线性**两种模式。两遍法 = 第一遍 `print_format=json` 出实测（input_i/tp/lra/thresh），第二遍把四个实测值喂回去 `linear=true` 纯增益对齐目标。
- **坑（本项目最重要发现）**：`linear=true` 有前提——目标 LRA 不得低于源 LRA、线性增益后 TP 不得超目标；**任一不满足时滤镜静默退回动态模式**，不报错不退出。动态模式会实时压扩，等于悄悄改了片子动态。这正是"卡不住还偷偷干"的教科书案例，我们现行 G4 链（单遍动态）其实就是这个模式的产物。
- `ebur128` 滤镜负责测量（I/S/M、LRA、真峰值），我们测量侧已用它，无需换。

### 3.2 `slhck/ffmpeg-normalize`（★1538，2026-09 仍在更新，MIT 协议）

- 两遍法 EBU R128 归一化 CLI（Python+ffmpeg），功能全：批量、跳过已达标、专辑/批次保相对响度、自文档化 `ENCODER_SETTINGS` 标签。
- **内置预设印证我们的量级**：`streaming-video` = −14 LUFS / TP −2 / LRA 7；`podcast` = −16 LUFS / TP −2；与我们口播现行目标 −14/TP −1.5 同档。
- **它防了那个坑但没有闸**：源码 `_media_file.py` 复核第二遍 stats，若被退回 dynamic 会算出**具体原因和可修数值**（"源 TP 太高：线性增益 X dB 后估 TP 会到 Y，超目标 Z → 把 TP 提到至少 W，或把目标降到至多 V"）——但只打 warning，照出文件。
- 借鉴价值：**它的警告算术就是我们要的罢工文案**——同样的公式，我们把它从 warning 升格为 fail + 标准出路（与 ⑰ 黑场"排布出路"同型）。不引入其代码：我们全链是"ffmpeg 直调 + 唯一入口脚本"，多引一个 Python 包只添依赖面，其算法核心本来就在 ffmpeg 里。

### 3.3 `csteinmetz1/pyloudnorm`（★783，MIT，纯 Python BS.1770-4）

- 不依赖 ffmpeg 的响度测量库（需 numpy/scipy）。只可能当"ffmpeg 缺席时的探测降级"候选。当前 ffmpeg 常驻 WorkTool，**暂不引入**（薄 harness 原则：不为不存在的环境预建双轨）。

## 4. 设计立场（三条原则，从用户裁决推导）

1. **测出来，不许猜**：一切响度数字必须 ebur128 实测落文件，注释/合同里出现的每个目标值配得上一张实测报告。（现行纪律已有，专员化后钉死。）
2. **有问题就卡住，不许偷偷干**（⑪ 直接沿用 09-24 帧率口径）：loudnorm 静默退回 dynamic = 拦；偏差超容差 = 拦；源素材到不了目标 = 在 G2 就把天花板摊开，不让人在 G4/G5 才发现。拦下必须给标准出路（提 TP／降目标／换源／压缩加强），学 ffmpeg-normalize 的可修数值算术，但从"警告"升格为"带算术的罢工"。
3. **单位说清**：LUFS（目标态）与 dB（增益量）分列，用户卡片上写人话（"整片平均响度""压低背景乐 X 分贝"），机器字段留 JSON 层。

### 5.2 分贝控制设计（拍板归属后开实现轮）

三道闸（与 ⑧ 早/中/晚同构）：

1. **G2 配音卡＝天花板披露**：每条 TTS/真人配音源文件实测 I/TP，预计算"最响可到多少"；够不到目标 → 卡片如实给出选项（放宽目标/加强压缩/换声线/接受带警告交付），**不得静默沿用**。
2. **G4 装配闸＝线性归一化+防回退**：口播链改两遍线性（测→喂 measured_*→linear=true）；跑完解析 loudnorm 输出 stats，发现 dynamic 回退或主轨偏差 > 容差 → 罢工，附可修数值三选一（提 TP/降目标/换源）。BGM 现行两条硬拦不动。
3. **G5 验收闸＝报告必过**：交付包新增 `loudness-report.json`（REQUIRED 第 15 件）；`--media` 对成片实测复核，偏差 > 容差 → invalid。R3 政策同样适用：历史封包不追溯、只补 contract-era 标记。

目标值与容差（默认=推荐，可调）：全片 integrated 目标 **−14 LUFS**、TP **−1.5 dBTP** 维持现行；容差建议 **±1 LU**（G4 装配闸）/ **±1 LU**（G5 复核）；LRA 只测不闸；平台档预设（如播客 −16）仅在包装决定卡显式选择时生效——目标值进计划的方式属实现细节，留实现轮定。
