### 专题：参考视频音轨的"解说噪声"问题（发现 → 处置 → 复现套路）

**问题**：参考视频音轨不是乐曲本体，是"人声解说 + 被逐句 ducking 的 BGM"成品混音。污染体现为：能量曲线出现句长周期的机械震荡（实测 `0.96/0.17/0.20/0.14…`）、人声辅音多计卡点、段间能量被压平（全挤在 0.13–0.18）。**识别信号：分析数字出现与乐曲结构无关的严格规律性 → 是剪辑痕迹，不是作品本身。**

**四层处置**：

| 层 | 手段 | 状态 |
|---|---|---|
| ① 执行免疫 | 驱动剪辑的卡点/对齐数字只来自用户自选**纯 BGM 文件**；参考片混音轨数字仅限"风格描述"，污染不传导到成片 | 架构天然（D10 分层红利） |
| ② 统计平滑 | 简报 `energyShape` 由 ~300 点原始曲线改为**最多 16 桶均值归一曲线**（桶宽≈10s > ducking 周期 1–3s，均值即低通滤波），并登记 `shapeBuckets`/`shapeBucketMs` 自曝分辨率；修后如实呈现"全程高能量、尾段收（0.584）" | 已修，合同同步，断言 +5 |
| ③ 诚实标注 | 报告 JSON 钉死 `mediaKind: video-with-audio`；回显卡（人读层）对视频来源卡头加"解说混音后的事实，非乐曲本体"+出路指引；纯音频卡不加 | 已修，单测 +2，zaku 卡已重渲 |
| ④ 根治缓行 | 人声分离预处理（Demucs 类，torch 栈 + CPU 分钟级）——当前无消费者需要，等 N2 出现"精确复刻参考片乐曲"真需求再评估 | 欠账 #13 |

**可复现套路（脏数据四步法）**：辨（规律性异常）→ 查消费链（能否用干净源隔离执行层）→ 平滑并登记分辨率 → 标注 + 根治挂账等真需求。一句话：**多数"数据脏"问题不必洗干净数据，要的是不让脏数据流向执行层，并让看数据的人知道它脏。**
