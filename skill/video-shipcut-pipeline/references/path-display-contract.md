# 路径展示合同

本合同区分**机器引用**与**用户回显**两层，适用于 G0–G5 的状态报告、节点交接、审批卡片和交付说明。

## 1. 两层必须分开

### 机器层

`pipeline-state.json`、G0–G5 manifest、审批决定和其他 JSON 合同中的路径字段继续保存普通路径字符串，例如：

```json
{"artifactRef": "工作区/剪辑方案/demo-001/G3-编辑计划.json"}
```

机器字段不得改写成 Markdown。脚本需要用原始路径做精确匹配、存在性检查和追溯。

### 用户回显层

面向用户展示的**已存在**本地文件或目录产物，必须写成可点击的 Markdown 链接：

```markdown
[显示名称](工作区/剪辑方案/demo-001/G3-编辑计划.json)
```

状态报告中的 `artifactRefs`、`inputRefs`、审批引用、验证帧、报告、字幕、音频、封面、预览、交接包和交付包清单，都必须按此规则展示。不要把用户回显路径放进反引号代码样式。

## 2. 链接格式

- 新项目链接目标只使用当前项目工作台下的相对路径；历史项目才使用只读 `工作区/` 或 `归档/` 链接。完整根路径见 [项目布局合同](project-layout-contract.md)。
- 使用 `/` 作为路径分隔符，避免直接展示 Windows 反斜杠路径。
- 不直接展示绝对路径（例如 `D:\...`）作为用户回显内容。
- 链接标签应说明产物用途或文件名，不使用模糊的“点击这里”。
- 只有实际存在的文件或可打开目录才能生成链接。
- 缺失产物写明 `未找到：<显示名称>`，不得生成指向推测路径的假链接。
- 目录只有在客户端能够打开目录时才链接目录；否则链接目录内的 README、manifest 或其他实际文件。
- 机器 JSON、命令参数和日志中的原始路径不要求、也不应强行变成 Markdown。

## 3. 节点最小回显要求

- **G0**：`工作台/<projectId>/G0-素材包/` 中的素材包、需求说明、授权说明、源素材、事实依据、参考资料和 BGM。
- **G1**：`工作台/<projectId>/G1-创作方向/` 中的方向简报、参考分析报告、关键帧/技术分析产物和继承的 BGM。
- **G2**：`工作台/<projectId>/G2-证据与口播/` 中的证据报告、证据清单、联系表、转写产物、批准口播稿、事实决定和试听音频。
- **G3**：`工作台/<projectId>/G3-剪辑计划/` 中的视觉分析、编辑计划、逐段时间表、验证帧、字幕、源字幕处理表、BGM 卡点表和封面候选。
- **G4**：`G4_ROOT` 中的可编辑工程、切片清单、独立口播、BGM、字幕参考、本地渲染报告、封面和实际 ChatCut 导出。
- **G5**：`G5_BUNDLE_ROOT` 中的最终视频、封面、字幕、时间线、源时间码清单、导出配置、QA 报告、delivery manifest、README 和实际失败样例。

## 4. 正反例

正确：

```markdown
- [G0 素材包](工作区/unicorn-gundam-intro-001/G0-素材包/material-pack.json)
- [G2 批准口播稿](工作区/unicorn-gundam-intro-001/G2-证据与口播/G2-口播草案-v0.1.md)
```

错误：

```text
`工作区/unicorn-gundam-intro-001/G0-素材包/material-pack.json`
D:\Video-shipcut\工作区\unicorn-gundam-intro-001\G2-证据与口播\G2-口播草案-v0.1.md
[G2 批准口播稿](工作区/unicorn-gundam-intro-001/G2-证据与口播/猜测的文件.md)
```

最后一项指向未经确认的文件，不能作为回显链接。
