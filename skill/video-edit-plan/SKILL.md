# 视频编辑计划

这是 G1/G3 Skill；正式项目产物分别写入 `工作台/<projectId>/G1-创作方向/` 与 `工作台/<projectId>/G3-剪辑计划/`。支持 G1「创作方向确认」和 G3「待审核编辑计划」。不执行 G4 实际剪辑、ChatCut 项目创建、上传或渲染成片。用户回显遵循 [Video-shipcut 路径展示合同](../video-shipcut-pipeline/references/path-display-contract.md)；方向和计划 JSON 中的机器路径保持原始字符串。

## 强制门禁

1. 取得素材包根路径 `--pack`，运行：
   ```powershell
   python skill/video-edit-plan/scripts/g1_direction.py check-pack --pack <素材包路径>
   ```
2. 仅在返回 `status: complete` 时开始引导。返回 `blocked` 时，只回显阻塞项并停止；不得提问、给候选或写入简报。
3. 先阅读 [G1 引导规则](references/g1-direction-guide.md) 与 [G1 方向选择卡](references/g1-choice-cards.md)。G1 继承 G0 已收集的信息（受众、平台、风格、BGM），只补充**标题、叙事角度、事实主张、表达边界**。回显摘要时只展示 G1 新增信息，继承信息简要列出；回显不是人工审批。

3.5 **参考视频深度技术分析**：若项目有参考视频，必须执行完整的深度技术分析流程（场景检测 + 已配置且获准的多模态视觉分析 + 转场分析），生成结构化技术分析报告。报告只写入 `工作台/<projectId>/G1-创作方向/`，不得污染原始参考视频目录。不得跳过此步骤或仅做表面印象描述。

3.6 **目标机体/主体确认**：G3 剪辑计划前，必须由用户确认哪些源视频片段包含目标机体（或目标主体）。多模态分析只能提供视觉观察，不能可靠替代具体机体身份确认；不得把任何模型自动筛选结果当成人工确认。若素材中目标主体戏份太少，应建议用户提供专门素材。
4. 将对话结果整理成 JSON，运行 `validate`。事实主张没有素材包内证据引用时只能标为 `pending`，不能写为已确认事实。
5. 回显摘要，收到用户明确确认后才运行 `write --confirmed`。默认遇到同名项目即停止，不能静默覆盖。

```powershell
python skill/video-edit-plan/scripts/g1_direction.py validate --pack <素材包路径> --input <方向输入.json>
python skill/video-edit-plan/scripts/g1_direction.py write --pack <素材包路径> --workspace <调用方工作区> --input <方向输入.json> --confirmed
```

输出只写入调用方工作区的 `创作方向/<projectId>/`，绝不回写素材包或修改原始媒体。`新工作区/` 是待验证提案，未明确启用前不得写入。输入 JSON、字段约束和简报格式见 [G1 引导规则](references/g1-direction-guide.md)。后续计划合同见 [计划合同](references/plan-contract.md)。

## Pipeline Integration

Read `工作台/<projectId>/pipeline-state.json`. Work only when `currentNode` is G1 or G3 and use only registered inputs. Archived files are never inputs. Record only the active node's artifacts and review points through `$video-shipcut-pipeline`; do not advance G2 or G4.

## G3：镜头、字幕和音频计划

先阅读 [G3 工作流](references/g3-plan.md) 和 [G3 目标素材视觉分析合同](references/g3-visual-analysis-contract.md)。只在 G2 审核决定为 `approved_for_g3` 时进入；不得按文件名、最近修改时间或聊天上下文猜测“最新口播”。目标主体筛选前必须完成 G3 关键帧和多模态视觉分析；联系表、转写或历史其他素材的分析不能代替它。若用户指定候选稿，先由 G2 写入该文件为 `approvedNarrationRef` 的审核决定，且明确事实来源层级，再进入 G3。

G3 必须：

1. 默认自动连续执行 G3.1–G3.5：拆解口播、发现候选、复用视觉文字索引、局部验证、生成时间线与包装计划，并运行全部结构和回显校验。用户不负责逐步触发这些中间工作。正常情况下，只向用户展示一次 G3.6 的完整最终审核回显，用户整体确认或按 `segmentId` 提出局部修改。只有自动检查发现主体、口播语义、动作连续性、时长、源字幕、BGM、授权或素材充分性风险时，才展示对应阻断项与必要的语义选镜审核回显；不得以过程性候选表冒充最终表。记录计划级 `humanReviewFeedback`。
2. 将最终时间线镜头收敛为逐帧切点，并为每段登记 `crop`、`mask` 或 `replace_clip` 的源字幕处理；源片烧录字幕不能依赖自动避让。
3. 输出可编辑字幕资产：ASS 为样式母版、SRT 为兼容副本、布局合同和逐镜头处理表。关键词只可作为同一 ASS 字幕块的富文本强调，禁止拆为独立居中图层。
4. 将标题/信息卡、口播、源字幕风险区分为固定车道；标题/信息卡与口播错开，不得竞争同一画面区域。
5. 登记 BGM 入出点、章节换句与动作重拍；仅使用获准音频，排除原片声音。
6. 锁定封面候选与标题版式。全文时长与目标冲突时，先请用户选择“压缩口播”或“调整目标时长”，不得静默删稿或改时长。
7. 完成后执行最终放行检查；未经 G2 放行、逐帧源字幕测试、时长确认和用户批准，不得标记 `approved_for_g4`。
8. 用户批准后，必须将**同一份**已校验的 G3 计划写为 `approved_for_g4`，并附 `g3Approval`、计划级 `timelineReview` 与每段完整 `visualVerification`。不得以摘要版、旧草案、单独验证清单或聊天中的批准替代 G4 执行输入。
9. G3 回显分为两类，不得混用：
   - **语义选镜审核回显**：用于 G3.1–G3.4 或阻断状态，固定列为 `口播槽位 ID | 输出时间 | 对应口播 | 候选 ID / 候选范围 | 实际画面观察 | 语义结论 / 风险 | 下一步`。`slot-xxx` 是口播槽位，`cand-xxx` 是待核验候选；它们不是 G4 片段。候选范围可以是探索范围，但必须明确标为候选范围，不能写进“源片区间”。
   - **最终审核回显**：只在每个口播槽位均已选出精确、连续、通过探针验证的镜头后生成。完整审核表固定为八列且顺序不可变：`片段 ID | 输出时间 | 对应口播 | 源片区间 | 用途 / 实际画面观察 | 语义匹配 / 主体状态 / 风险 | BGM 乐句 | 转场指令`。第一列必须是可执行的 `segmentId`，源片区间必须是精确切点；禁止出现“未生成”“无”“待缩窄”或其他候选占位文本。

   两类回显均须在表后附 BGM 乐句说明，明确其不是逐拍卡点。修订可以先显示简短变更摘要，但提交最终审核时必须重新显示完整八列表。用户要求“看最终回显”时，必须在对话中原样展示完整审核表和 BGM 说明；不得只摘录阻断项或执行摘要。回显只能汇总已登记字段，不能将编辑推断写成已验证事实。旧回显仅可归档；仍被项目状态审批引用的版本不得移动。

   **回显强制校验：** 先把回显写成版本化结构化 JSON，不得直接手写 Markdown 表。渲染用户可见表格前，必须运行：
   ```powershell
   python skill/video-edit-plan/scripts/validate_g3_callback.py --callback <G3-回显数据.json> --plan <G3计划.json>
   ```
   `final_review` 只有校验成功后才可称为“最终审核回显”或“最终回显”。校验器强制八列表头及顺序、每个 `seg-xxx` 与计划精确切点一一对应、每行必填字段、从 0 到 `durationMs` 的完整连续覆盖、已验证画面和 `direct_match/not_applicable` 语义状态。失败时不得删行、缩写或降格称为最终版；只能修正数据，或以不传 `--plan` 的 `semantic_selection_review` 形式回显未完成槽位。
10. 每个最终片段必须登记它覆盖的口播 `narrationStartMs/narrationEndMs`、逐字口播文本、叙事对象/属性和 `semanticAlignment`。当口播介绍外观、模式变化、武器、动作或人物反应时，实际画面必须直接呈现该对象/属性；“同一主题相关”不能替代语义匹配。无法匹配时，标记 `semantic_mismatch` 并更换镜头、调整口播或回到 G2，禁止进入 G4。
11. **素材充分性分流：** 在 G3.3 完成候选筛选后，先统计“不重复、通过语义匹配且可处理画面风险”的可用时长，并按口播节拍分别比较。若任一核心节拍缺少所需主体画面，或总可用时长不足以覆盖获准口播，不得用无关剧情、敌方主体、静帧延长、循环或无意义慢放补齐。必须向用户给出三项选择：补充已授权的目标主体素材；缩短 G2 口播并重新获准；或把口播改写为可由现有语境画面直接承载的表达。用户选择短版后，G2 必须产出新的唯一获准稿、同源完整旁白与时间码，G3 只为该短版重建计划。

### G3 子节点与语义对齐门禁

G3 依序执行六个子节点：`G3.1 口播节拍拆解`、`G3.2 候选发现`、`G3.3 语义选镜`、`G3.4 局部视觉验证`、`G3.5 时间线与包装计划`、`G3.6 完整回显与人工放行`。

- G3.1：把唯一获准口播拆为带时间范围的语义节拍；每个节拍登记所述对象、属性/状态/动作或人物反应，以及画面必须可见的最低证据。它不是重写口播，不能改变 G2 的事实状态。
- G3.2：按分层抽帧和已确认主体范围发现候选，只生成实际观察，不得因口播需要而倒推画面事实。
- G3.3：用“节拍的最低可见证据”筛选候选并逐段登记 `semanticAlignment`。这是第一次硬门禁；主题相关但未直接呈现主张的候选必须标为 `semantic_mismatch`，不得进入时间线。
- G3.4：对入选候选按镜头层/主张层采样，逐探针核验画面是否仍满足该节拍的最低可见证据。这是第二次硬门禁；镜头内发生状态变化、混入无关画面或关键属性不可见时，必须拆段或换镜头。
- G3.5：只消费已通过语义验证的片段，安排连续时间线、BGM 乐句、字幕车道、源字幕处理和转场意图。转场意图服务于已成立的语义，不得修补语义错配。
- G3.6：完整八列表按节拍汇总口播、画面观察、语义结论、BGM 和转场，供用户一次性审阅。`semantic_mismatch`、缺少口播映射或缺少探针证据，均阻断 `approved_for_g4`。

不要把参考视频的原句、画面、音乐、Logo 或品牌视觉带入输出。G3 只准备 G4 可编辑交接物；不得创建 ChatCut 项目、上传素材、实际剪辑、渲染或发布。任何外部上传或分发都需要用户单独授权。
