# 最终回显样式指南（六节点通用 v1.2）

用户 2026-09-11 定案落地（N8 活测问题⑰：行话漏进人话卡、信息不结论先行、单卡模板未收敛）。v1.2（2026-09-23 验收003 修复批次）：全卡默认推荐（⑮）+ 唯一关单口令语义（㉖）。
适用：各节点呈给用户的**最终审核回显卡**（G1–G5 门禁卡，含单卡模式下并入的全部决策点）。
不适用（保持原样，按内联原则进本卡第④区）：专员固定表格卡（BGM 分析/检索词/推荐/试听回显等）、G3 八列硬校验表、G0 资料清单块。

## 五段骨架（顺序与段名固定）

1. **一句话结论**——这张卡要你拍板什么，人话说清，不超过两行。
2. **决策点**——节点合同要求的决策项**一个不少**；每项固定三小节呈报：**问题**（一句话，这人要定什么）→ **选项**（A/B/C…列全，自定义永远可选）→ **【默认已选：X｜依据：…】**（≤两行）。用户亲定的写【用户定案】不得冒充默认；归属如实（验收推荐≠用户选择）。用户有意见直接说换哪个选项，没意见进⑤确认。
   - **全卡默认推荐（用户 2026-09-22 裁决，issue ⑮）**：一切用户可见选项卡——含专员固定表格卡、充分性三选一、身份/验收裁决卡（覆盖 09-11"永不预选"旧条款）——必须自动给出【默认=推荐｜理由】，用户直接确认即接受默认；无默认推荐的卡不合格。充分性缺口的默认=**缩短/改写回 G2**，补素材降为用户点名选项。
   - **唯一关单口令语义（issue ㉖，sinjuku 实片事故）**：终审卡上存在待批提案时，精确关单口令**只能等于"接受默认推荐"**；"按现状关单/放弃推荐"必须另给显式不同口令（如 `确认G3-现状`）并在卡上写明两者指向不同批准对象。**禁止同卡双义**——收尾句与推荐项指向不一致=卡片起草缺陷，用户按默认直觉确认受害时按事故 reopen 处理，不得记"用户已确认"。
3. **待办与事实状态**——用户必须亲手办的事（截止点+后果一句话）、pending 事实缺口、红灯警示：只给结论，证据指向④。
4. **证据与产物**——**所有机器字段与数字只准出现在这里**：文件链接、ID、SHA、枚举值、dB/LUFS 等；本区首行标注**项目绝对根路径**（N8 问题⑯教训）；专员回显卡按内联原则附于本区。
5. **操作区**——否决示例一句话 + 精确门禁口令。

## 禁词表（对第①–③段生效）

- 机器枚举值不得上正文：如 `editorial_expression`、`uncleared-platform-catalog`、`libraryPending`、`capability_missing`——①–③段用人话翻译（"标题是观点句""还没拿到授权""这台机器暂时没耳朵"），原字段只进④。
- 内部黑话不得上正文：槽/翻槽/grant/锚/桶/门禁收据等——正文写"选曲登记已确认/许可升级/参照曲"；字段名与文件只进④。
- SHA、neteaseId、时间码精度数字不进①–③段正文。

## 冲突裁决

样式指南不改任何门禁硬校验（G3 的 JSON→渲染八列表仍是机器强制）；单卡骨架与既有门禁合同冲突时，**以门禁合同为准**，硬校验表视为第②段的组成部分内嵌呈现。
