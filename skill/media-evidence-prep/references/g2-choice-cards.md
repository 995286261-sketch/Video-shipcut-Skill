# G2 事实与口播选择卡

G2 在完成证据准备后，先展示结构化选择卡；用户不需要读完整证据报告或从零写口播。前三项由 Agent 根据 G0/G1、素材和事实资料生成，第 4 项固定为自定义。

## 1. 事实处理方式（四选一）

1. 保守创作：仅使用已登记且可追溯的资料；其余内容不写入成片。
2. 本项目限定采用用户提供资料：将用户提供的截图、聊天确认或页面资料标为“仅本项目确认”，不得升级为官方一手事实。
3. 等待客户正式资料：只完成证据整理与素材风险清单，暂不生成可放行口播。
4. 自定义处理方式（自己填写）。

## 2. 口播方向（四选一）

前三项由当前 G1 方向与可用事实生成，并标注每项的可用事实、编辑表达和风险。物流品牌示例：

1. 稳健品牌型：以“清晰安排、值得信赖的伙伴”为编辑表达；只使用已确认服务事实。
2. 运输行程型：以出发、装载、行程、抵达的叙事顺序组织；道路画面只作氛围，不能推导服务范围。
3. 沟通条理型：强调沟通、衔接和秩序感等编辑观点；不写成已经证实的服务承诺。
4. 自定义口播方向（自己填写）。

## 3. 音频策略（从 G0/G1 自动继承）

展示但不重新询问：BGM 决策、已登记音频、原声策略与分发限制。用户仅在要改动时选择：

1. 沿用 G0/G1 音频策略。
2. 修改 BGM 决策（明确填写新值）。
3. 修改原声策略（保留 / 排除，并说明原因）。
4. 其他（自己填写）。

若选择“已提供 BGM”，自动展示 G0 中已登记的文件、使用范围和哈希；不得要求重复提供路径。若 G0 尚未登记音频，显示“回 G0 补充 BGM”，不得擅自用其他音乐替代。

## 3.5 响度天花板披露（响度接线批一，2026-09-28）

配音候选文件（试听片段或整条旁白）落盘后，G2 对**每条候选配音源**调用响度专员：

```text
python3 skill/loudness-expert/scripts/loud_measure.py --input <配音源> --output-dir 工作台/<projectId>/G2-证据与口播/响度/ --project-id <projectId>
python3 skill/loudness-expert/scripts/loud_plan.py --input <配音源> --profile video --output-dir 工作台/<projectId>/G2-证据与口播/响度/ --project-id <projectId>
```

- 试听卡每个候选附加一行披露：**“整片平均响度最响可到 X LUFS（目标 −14 LUFS）”**——X 逐字取自《响度-归一化计划》的 `ceilingLufs`，呈现层零算术；措辞由专员自主，数字不许改、不许"大约"。
- 天花板够不到目标（计划 `blocked_*` 或 `ceilingLufs` 低于目标）：**同轮出选项卡**，出路逐字取自产物 `exits`（提峰值上限 / 降目标 / 先压缩 / 接受带警告交付），不得静默“到 G4 再说”；用户选择记入审批留痕。
- 选定配音对应的计划文件写入 G2 决定的 `loudnessPlanRef`；`validate_g2_decision.py`（schema **0.2**）机验产物身份（skill/purpose 头）与旁白源 sha256 对账——**批准后换配音 = 门禁自动失效**，必须重新合成→重新规划→重新渲卡请批（R2 同型纪律）。
- 本披露不新增门禁、不新增卡片轮次：并入现有配音试听确认，批准动作仍是一次 `确认 G2`。

## 4. 配音语言与口音确认（口播定稿前，动态四选一）

G0 中的语言、口音、声线、语气和语速是偏好记录，不等于已确认的成片配音。G2 先扫描本地实际可用的配音来源（已登记的客户配音、已安装且可调用的本地声音、或项目允许使用的现有音频），再生成选择卡。A-C 必须来自扫描结果，不能凭空编造；如果实际只有一项可用，就只显示这一项和自定义项，不得为了凑满四项虚构声音。

1-3. Agent 从实际可用来源中推荐的配音选项：每项必须显示语言、口音、声线、语速、来源状态、可用范围和**成片分级**。分级默认两档：神经 TTS（如已获授权的百炼 CosyVoice）或真人配音为 `成品级`；macOS 系统声音（`say`）默认 `预览级`，且必须注明”系统 TTS 有人机感，仅用于确认节奏与断句，正式成片需神经 TTS 或真人替代”——不得在未告知分级时让用户按”能听”通过。**预览级升成品级的唯一通道（2026-09-29 用户拍板开绿灯）**：用户在试听卡上逐字显式批准（批准原话必须含”预览级”披露词，如”接受预览级用于正式成片”），批准原话登记进 G2 审核决定的 `previewTierProductionApproval` 字段，校验器机验在场；不批则预览级只能做草稿声。禁止事后追认、禁止 Agent 代批——口子只放”知情用户拍板”，分级披露一个字不松。
4. 自定义配音要求（自己填写）。

若没有任何可用配音来源，直接显示“暂无可用配音，请提供音频或安装/启用本地声音”，并暂停，不得假设存在普通话、英语或其他音色。G2 在生成口播草案后、请求“确认 G2”前，必须为每个可用选项提供不超过 8 秒的本地试听片段；试听与完整旁白合成都统一运行 `scripts/local_tts.py`：声线未安装即结构化 blocked（禁止 macOS 静默回退成读不了中文的英文音色）、逐句产出 wav 与**实测时长**清单、系统声音清单固定标注 `voiceTier: preview_only`；需要机器自检时加 `--verify-asr --asr-initial-prompt <专名词表>` 做 ASR 回读比对。旁白若走外部合成通道（如已获授权的百炼 CosyVoice）而不经过 `local_tts.py`，回读改用 `scripts/local_transcribe.py --initial-prompt <同一份专名词表>`（⑨：无词表通道时小模型把专名全听成同音误字，逐词比对假阴性一片红）；机器比对仍有同音假阴性时，可由人工判读“同音=通过”关单，但判读结论必须如实记入配音清单 `asrSelfCheck`，不得写成机器通过。试听确认必须记录：语言、口音、声线描述、语速、来源引用、试听文件引用、成片分级、`G2-配音清单` 的实测总时长和用户选择。用户可以要求重试；未明确确认前，G3/G4 只能保留 `voice_pending`，不得合成或锁定完整旁白。此项确认与“确认 G2”可在同一轮完成，但两项都必须明确记录。

## 5. 排版稿回显（蓝图项目专用，N9；2026-09-10 用户定稿）

走过节拍蓝图循环（`g2-script-review-gates.md` 3.5 节）的项目，口播稿请批时**必须逐句带目标时间码回显**——纯文本稿不足以让人审"排版"，批的到底是文本+意图两层。格式固定为一张表：

```text
【G2 排版稿 · 请批】蓝图：BGM-节拍蓝图-v<version>.json（句边界设计目标=贴鼓点栅格）
| 句 | 目标时间码 | 时长 | 乐句/档位 | 边界→最近鼓点 | 文本 |
| N01 | 00:00.000–00:07.200 | 7.2s | P1/留白 | +0ms / -40ms | …… |
```

- 目标时间码是**设计意图**；TTS 合成后本表以实测时间码重渲染一次（列名改"实测时间码"，增"意图偏差"列），偏差超吸附容差的句子按 3.5 节第 5 步回改稿循环，不得放行 G3 硬凑。
- 本卡随创作卡同轮请批，**不新增门禁**：批准动作仍是一次 `确认 G2`，门禁收据的 basisRefs 增加排版稿文件。
- 产物：`工作台/<projectId>/G2-证据与口播/G2-排版稿-v<version>.md`（文本+目标时间码），与口播稿、配音清单互相引用。
- 纯旁白型（跳过蓝图）不出本卡，维持原纯文本口播稿回显。

完整定稿形态（四卡 + 自动回显 + 排版稿卡一套）见样例 [examples/G2-完整回显样例-zaku.md](examples/G2-完整回显样例-zaku.md)。

## 回显密度纪律

给用户看的回显只含两件事：**结论**（一两句人话：材料齐没齐、发现什么问题、影响是什么）与**待拍板项**（每张卡一行一个选项）。内部编号体系（claim ID、来源 S 编号、supported/pending 级别、哈希、警告清单）一律只写进产物文件，不进对话回显；用户想深挖时自己点链接。四张卡在一屏内读完是硬标准。

## 自动回显，不构成人工审批

选择后自动展示。所有产物路径必须写成可点击的 Markdown 超链接 `[文件名](相对路径)`。

- 可说事实 / 本项目限定事实 / 待确认事实 / 禁止表述；
- 可用视觉 / 仅氛围视觉 / 默认排除视觉；
- 口播草案、预计时长（合成后一律以 `G2-配音清单` 的实测时长为准回显）、每句所依赖的事实或编辑表达；
- BGM、原声与分发限制；
- 待补资料清单。

回显格式示例：

```text
【G2 证据与口播确认】

📁 证据产物：
- 联系表：`工作台/<projectId>/G2-证据与口播/联系表/<asset-short-id>-contact-sheet.jpg`
- 转写：`工作台/<projectId>/G2-证据与口播/转写/<asset-short-id>/transcript.srt`
- 报告：`工作台/<projectId>/G2-证据与口播/G2-证据准备报告-v<version>.md`

🎙️ 口播草案：`工作台/<projectId>/G2-证据与口播/G2-口播草案-v<version>.md`
- 方向：设定科普型
- 时长：约 110-120 秒

🎧 配音试听：
  - `工作台/<projectId>/G2-证据与口播/配音试听/voice-audition-yunjian.mp3` - YunjianNeural（有力、激情）
  - `工作台/<projectId>/G2-证据与口播/配音试听/voice-audition-yunyang.mp3` - YunyangNeural

🎵 音频策略（继承自 G0/G1）：
- BGM：[aji-yema-3only-indulgence.mp3](工作台/<projectId>/G0-素材包/07_授权音频/aji-yema-3only-indulgence.mp3)
- 原声：排除
- 分发：仅内部测试
```

自动回显只用于发现遗漏。事实裁决、已批准口播、试听/声音决定和固定 G2 卡必须先完成并登记为机器可验证的 G2 门禁收据；只有用户精确回复 `确认 G2` 时，才记录 `approvedNarrationRef`、`factCitationRef` 与 `voiceBriefRef` 并放行 G3。
