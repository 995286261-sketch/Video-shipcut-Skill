# G2 事实与口播审核门禁

适用场景：用户给出参考视频口播稿/转写与自己的素材、事实资料，要求生成原创口播稿。

## 标准协作流程

在任何口播草案前，先执行 `g2-choice-cards.md` 的四选一事实处理与四选一口播方向。音频策略必须继承 G0/G1；不得在 G2 默认重置为“无 BGM”。

### 0. 先锁定用户意图

在动笔前，确认并记录：主题、目标观众、目标时长、参考稿、允许借用的内容层级、用户已定稿段落、允许续写的锚点、章节布局、事实资料、剧透边界、声音与音乐策略。没有明确授权时，不得改写锁定段落，也不得把创作候选直接升级为可渲染稿。

### 1. 拆结构，不抄表达

把参考稿抽象为章节职能，例如“引言 → 历史 → 发生了什么事情 → 做了什么 → 成果/实战”。为每章写一句本片的叙事问题和预期作用，不复制参考稿的连续措辞、专有事实或结论。

### 2. 建立事实地图

对每章建立三栏：`可播事实`、`编辑观点`、`待核验/剧透项`。每个事实句必须附来源与定位；编辑观点必须显式标记；待核验项可以保留在创作稿中，但不能进入 `approved` 稿或 G3 输入。

### 3. 分层产出

依次输出：

1. `创作候选稿`：保留用户表达和节目气质，允许待核验标记。
2. `事实审核稿`：仅保留可追溯事实与已确认编辑观点。
3. `审核决定 JSON`：标记哪一版是 G3 唯一输入、禁止项、音频策略和未决项。

禁止用审核稿覆盖或删除创作候选稿。用户确认创作候选稿后，先记录为 `creative_locked`；完成事实审核后才标为 `approved_for_g3`。

### 4. G3 交接

G3 只能读取 `approved_for_g3` 稿及其审核决定。若项目只锁定创作稿，G3 状态保持 `blocked_on_fact_review`；不得用旧稿、未审核稿或参考稿自行补事实。

## 可直接采用的三类工作规则

### 1. 用户草稿优先与时长预算

用户已定稿的段落是锁定输入。除非用户明确要求，不得改写它；新版本只能从用户指定的锚点之后继续写。先按目标声音与语速估算每一段是否适合成片时长，留出镜头、信息卡和停顿空间。

### 2. 先摘证据，再写事实

先从已登记的一手/官方资料摘出逐条可播主张与定位，再写事实句。每一条客观事实必须能回指到来源；资料未覆盖时，标为 `needs_fact_review`，不能用“听起来合理”的内容补足。

### 3. 参考只借结构，不能借表达

参考视频只可提取抽象结构，例如“时代锚点 → 反常画面 → 前代问题 → 新方案 → 回收钩子”。不得复用连续措辞、专有事实、素材、音乐、Logo、字幕或品牌视觉。交付前需人工检查候选稿与参考转写：若出现连续 8 个以上相同汉字，或一句话仅替换实体名，应改写并登记。

## G2 必交付

1. `approved` 或 `needs_fact_review` 的口播稿，并标明锁定输入与新增段落边界。
2. 事实引用清单：事实句、来源、定位、适用限制。
3. 编辑观点清单：不得伪装成官方设定。
4. 参考原创性检查：说明借用了哪些结构，不复用了哪些表达。
5. 口播时长估算与声音 brief。
6. 章节地图：章节目标、事实 ID、编辑观点、待核验项和预计时长。
