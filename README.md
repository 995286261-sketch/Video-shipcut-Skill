# 长视频切片与本地自动成片 Skill

一套面向长视频二次剪辑的**本地化、可追溯**自动成片流程，以 Agent Skill 的形式组织：用户提供已授权的本地素材和一句剪辑意图，系统经过六个节点、人工审核门禁、确定性本地处理和质检，输出可播放成片与完整交付证据。

## 第一次来，先对号入座

| 你是谁 | 你只要做什么 | 接下来会发生什么 |
| --- | --- | --- |
| **想剪片子（用户）** | 用你的 Agent 打开本仓库作为工作目录，说一句人话："我有一批素材在 <某目录>，帮我剪一条 <主题> 视频" | 系统自动路由进流水线，从 G0 开工单开始——九个问题一张卡、一次答完；此后每个节点结束出一张固定格式的回显审核卡。你全程只需要**回答问题、看卡、批准**，不需要读任何代码或文档 |
| **想确认这套东西真能跑** | 跑「一分钟自检」那条命令（见下） | 每个测试文件末尾打印 `OK` 即工具链健康；环境依赖缺什么，开工时会当场点名 |
| **想改造或扩展它** | 先读根目录 `AGENTS.md`（路由与红线）和 `目录规范.md`（skill 花名册） | 所有 skill 物理平铺一层；新增专员按花名册登记 |
| **在评估这个项目** | 往下读「解决什么问题」「六个节点」和版本日志 | 每条工程原则都能沿版本日志找到对应日期与变更明细 |

## 用起来的节奏（三步，循环六次）

1. **AI 问，你答。** G0 一张开工单卡问齐九个问题（主题、素材位置、授权范围、分发去向、配音、品牌、BGM 等）；中途只在必须人来裁决的分岔处插卡。
2. **每个节点末出一张回显卡。** 固定五段——一句话结论 / 决策点 / 待办与事实状态 / 证据与产物 / 操作区；表格呈现，时间码一律人类可读。
3. **你逐字批准，门禁才放行。** 批准口令原话入册进项目状态文件；发现问题可以返工（reopen 重批），旧批准与历史永不消失。

六个节点（G0→G5）各走一遍这个节奏，最后拿到可播放成片 + 完整交付证据包。

## 解决什么问题

自动剪辑常见的失控点：画面与口播不对应、素材授权不清、方案只存在对话里无法交接、成片无法追溯、出问题只能推倒重来。本工作流的原则是**每一步都要有所依据**——事实有出处、决策有留痕、产物有指纹、门禁有口令。

## 六个节点

| 节点 | 做什么 | 人工门禁 |
| --- | --- | --- |
| G0 素材受理 | 开工单收集需求，登记素材与授权 | 确认开工单 |
| G1 创作方向 | 主题、风格、参考分析与 BGM 选型 | `确认 G1` |
| G2 证据与口播 | 事实核证、转写、口播稿与配音确认 | `确认 G2` |
| G3 编辑计划 | 逐段切点、转场、字幕、封面规划 | `确认 G3` |
| G4 本地剪辑渲染 | 确定性本地装配、混音、烧录（可选 ChatCut 路线） | `确认 G4` |
| G5 质检交付 | 全量解码验收、交付包封存 | `确认 G5` |

每个节点完成时向用户呈现一张固定格式的回显审核卡，批准口令逐字留痕；未过门禁不得推进下一节点。

G0 收齐答案后、正式开工前，流水线会自动跑一次**能力盘点**：按这单活要用到的能力（找乐、配音、烧字幕、转场……）逐项实测本机工具箱，缺口当场点名并给出补法，绝不带着缺口往后跑——这是"缺口必须在开工前申报"的机器闸，装配环节还会核对盘点账本（旧账即罢工，唯一豁免是用户逐字原话）。

## 一分钟自检

```bash
for f in skill/*/tests/test_*.py; do python3 "$f"; done
```

测试全部纯标准库 `unittest`，python3（≥3.9）即可运行，每个文件以 `OK` 收尾为绿；个别文件会真调 PATH 上的 ffmpeg，本机没有的话它们会如实罢工——这正是能力盘点要申报的那类缺口。依赖与可移植性约定见 `skill/p0-c-pipeline/references/runtime-dependencies.md`，盘点机制的合同文本见 `skill/p0-c-pipeline/references/capability-audit-contract.md`。

## Skill 包一览

所有 Skill 平铺在 `skill/<name>/`（内含 `SKILL.md`、`scripts/`、`references/`、`tests/`），物理扁平、逻辑分组。

### 节点专员（流水线内，负责编排与审核卡）

| 节点 | Skill | 职责 |
| --- | --- | --- |
| 编排 | `p0-c-pipeline` | 六节点路由、门禁口令与项目状态记录 |
| G0 | `material-pack-intake` | 素材包创建、校验与登记 |
| G1 / G3 | `video-edit-plan` | 创作方向确认 + 剪辑计划 |
| G2 | `media-evidence-prep` | 转写、证据、口播与配音准备 |
| G4 | `local-video-render` | 本地剪辑、装配渲染、ChatCut 交接 |
| G5 | `media-qa-delivery` | 终检 QA 与交付打包 |

### 功能专员（跨节点能力，不在门禁内）

| 专员 | Skill | 干什么 |
| --- | --- | --- |
| BGM 专员 | `music-expert` | 找歌、试听、节奏分析、混音合同与 BGM 链审计；经验库 `experience/music/` |
| 字幕专员 | `subtitle-expert` | 字幕布局校验、cue 修剪、SRT 复检；经验库 `experience/subtitles/` |
| 转场专员 | `transition-expert` | 转场词表与计划深检、执行指令派生、装配复检审计 |
| 响度专员 | `loudness-expert` | 响度实测、归一化规划、验收复测与回显卡（LUFS/dBTP 口径） |

节点专员只管编排和卡片，跨节点能力全部走功能专员，产物握手交接。另有 `long-video-local-edit` 仅供历史项目兼容检查，新项目不使用。

## 仓库结构

```text
skill/        上述节点专员与功能专员 Skill 包（一层目录）
experience/   跨项目经验库（音乐、字幕；只存事实档案，音频本体永不入库）
工作台/       现役项目的正式节点产物（按 projectId 分 G0–G5 子目录）
docs/         设计与接线方案文档
examples/     渲染配置示例
CHANGELOG.md  完整版本记录
VERSION       当前版本号
```

## 快速开始（给一个新项目）

1. 把本仓库设为 Agent 的工作目录——入口路由与红线写在根目录 `AGENTS.md`，Agent 会自动接管，你不需要点名任何 skill、也不需要准备技术工件。
2. 对 Agent 说一句剪辑意图，附上素材所在目录。
3. 跟着卡走：答九问 → 逐节点看回显审核卡 → 逐字给批准口令。

**东西落在哪**：素材本体永远待在你自己的目录里，系统只读、不改、不搬。**第一次开工时系统会问你一次**：成片工地放哪——甲（推荐）仓库内 `工作台/`，乙你指定的其他目录（如大容量盘）；你逐字答一次，机器记账，之后所有新项目都按登记住址落盘，越界开工直接罢工（选址是人的决定，AI 不能替你选，也不会每次烦你）。每个项目的全部正式产物（工单、依据、登记件、批准留痕、交付包）写进 `<登记根>/工作台/<projectId>/`，其中 `pipeline-state.json` 是项目状态唯一事实源——中途停下，第二天新会话报项目 id 即可从当前节点续工。仓内现存的 `工作台/` 项目是本流程的实录样例，供翻阅；你的新项目会自动新建自己的目录，与它们物理隔离。合同文本见 `skill/p0-c-pipeline/references/workspace-root-contract.md`。
