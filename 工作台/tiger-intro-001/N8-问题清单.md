
### ㉗ validate_g3_plan：review 阶段与 approval 阶段规则不对称（G3 关单实测）
- 现象：`mappingMode="sequence"` 与 `timelineReview.status="approved"` 在 review_required 模式下都能通过校验；改成 approved_for_g4 后同一校验器才报错（且仍单错报出），关单阶段来回两轮。
- 期望：review 模式就应校验所有后续阶段字段（词汇表一致），或文档给出 approved 模式专属校验清单（并入 ㉕ 的字段清单诉求，单独记是因为这次是"模式不对称"而非"字段未知"）。

### ㉘ G1 风格规则无机器落点：顶部标题栏/双语字幕在 G3 合同中空转（G4 实测发现）
- 现象：G1 方向简报风格规则写明「借鉴《冷战奇迹》：顶部固定标题栏、底部中英双语字幕」，但 G3 机器合同（packagingDecisions/字幕布局）只登记了中文单语口播字幕、无标题栏字段；G4 按「未登记图形不得入输出」纪律只能照 G3 执行，风格规则静默丢失。
- 期望：G1 风格规则要么有结构化字段并可被 G3 校验器强制承接，要么在 G3 门禁卡上显式列出「本条风格规则未落入合同」让人拍板；不能靠人肉比对方向简报。
- 本测处理：候选成片按已批准 G3 合同渲染（无标题栏、无英文行），差异在 G4 回放卡上向用户披露，由「确认G4」或修改意见裁决。

### ㉚ G4 入口脚本不校验输出目录=合同 G4_ROOT，错误到 approve 才暴露
- 现象：g4_prepare/g4_render 接受任意 --output-dir，我把 G4 产物写进了自创的 `G4-剪辑执行/`（合同规定 `G4-剪辑与渲染/`），一路 valid；直到 pipeline_state approve 才报 "localRenderRef must be under the active G4 directory"，被迫整目录改名+全量路径回填。
- 期望：prepare 第一步就用 project_layout 校验 output-dir 等于 G4_ROOT，不匹配直接 blocked；守卫不应只在关单处。

### ㉛ drawtext 用 ttc 首 face 导致简体缺字（G5 封面实测）
- 现象：p0c-ffmpeg drawtext fontfile=/System/Library/Fonts/PingFang.ttc 渲染「战场/对手/队」为豆腐块（首 face 非 SC 覆盖）；libass（subtitles 滤镜）同字体同文字完全正常。
- 影响：g4_assemble --title-bar / --cover 的 drawtext 路线在客户成片上会静默产出缺字图形，且无校验。
- 期望：图形文字统一走 libass（ASS 样式合同），或 drawtext 后强制抽帧 OCR/人工检查；文档标注 ttc 陷阱。

### ㉜ source-timecode-list.json 无 schema 文档，builder 与 validator 要的形状互斥
- 现象：g5_build_delivery_manifest 读顶层扁平 segments[]；g5_validate_delivery 又要求 chapters[].segments 为字符串 ID 列表，传对象列表直接 TypeError（unhashable dict）。两处期望未写进任何合同文档，只能靠撞错试出。
- 期望：bundle 合同文档给出该文件唯一 JSON Schema，两个脚本共用同一校验。

### ㉝ g5_validate_delivery 隐性 schema（checks 名/artifacts 键/chapters.output/export.projectId/codec 形状）全部无文档
- 现象：QA_CHECKS 要求 decode/videoCodec/…/duplicateSegments/cover 十个键名；artifacts 要求 finalVideo/cover/subtitles/chapterClips 特定键；chapters 要求 output 指向包内文件；export-config 要求 projectId+video.codec+durationActualMs；manifest 要求 finishedAt 非空。全部只能撞错反推（且 --media 一次 12 条算是好的一面）。
- 期望：bundle 合同文档给出每个组件文件的完整 schema 与示例；builder 与 validator 共享同一 schema 定义。
