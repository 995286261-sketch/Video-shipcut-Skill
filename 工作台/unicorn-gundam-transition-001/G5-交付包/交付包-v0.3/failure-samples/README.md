# 失败样本记录（本轮 G5 实跑抓到的真实缺陷）

本目录记录封包前被门禁/握手/人工抓到并已处理或如实披露的缺陷。圈号对应项目《问题清单-v0.1.md》。样本帧见 `工作台/unicorn-gundam-transition-001/G4-剪辑与渲染/抽帧检查-v0.1/`。

## ⑦ 字幕轴 50ms 重叠（G5 握手抓到 → 第 2 轮修订闭环）
- 现象：G3 批准的 SRT v0.1（照搬旧项目）cue1 结束 5372ms > cue2 开始 5322ms；烧录 ASS 继承（两行同位撞 1.5 帧）。
- 抓到环节：G5 `subtitle_check_srt.py` 握手判 failed。
- 处理：reopen-g3 → SRT v0.2（cue1 收至 5322）→ ASS v0.2 → 候选 v0.2 → G3/G4 重批；5.30s/5.34s 抽帧复核单行无碰撞。
- 教训：克隆照搬旧产物必须按现行校验重跑（G3 登记只查存在性，内容校验接在 G5=批准者不看检验单）。

## ⑧⑨ 成片帧率 24fps ≠ 批准/源 30fps（G5 媒体探测抓到 → 第 3 轮修订闭环）
- 现象：候选 v0.1/v0.2 实为 24fps，G3 卡包装决定与源均为 30fps。
- 根因：克隆重建的计划漏写 fps 机器字段 → 工程清单 targetFps:null → 渲染/装配按硬编码默认 24 静默降帧（⑨：预览器与装配器读 fps 的位置还不一致，属单一事实源缺失）。
- 处理：reopen-g3 → 计划双位置补 fps:30 → 预览重跑免 --fps（修复自证）→ G4 重渲候选 v0.3 = 30/1、1165 帧、fpsSource=manifest-targetFps → G3/G4 第 3 轮重批。
- 教训：人读卡说 X ≠ 机器编了 X；默认值是幻觉面，缺失应报错不应猜。

## ⑩ 修订轮后 BGM 链路审计 planFileHash failed（如实披露，待人工裁决）
- 现象：`bgm-chain-audit.json` 16 链路 15 过、planFileHash failed——混音合同锁定的计划指纹仍是第 1 轮版本（DB6426CB…），第 2/3 轮修订+盖戳改写计划文件为 c251e92e…。

- 处理：不动刀、不改合同；写入 QA 报告 bgmChainAudit=failed + 警告清单，G5 卡交人工裁决。
