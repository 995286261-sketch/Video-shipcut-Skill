⑫｜找乐时长合同三层失守（真机全形态集齐，比 sinjuku 时代认知更深）｜
　(a) **API 参数无声失效**：`music_search_freesound.py` 把 `min_duration/max_duration` 作为查询参数发给 Freesound 文本检索端点，服务端不识别、静默忽略——11-19 三轮实证：terms-file 轮声明 `mode=hard, appliedMinSec=100` 而池内含 11.688s/28.5s/39.7s 曲（ffprobe 与 API duration 字段吻合，排除预览截短因素）；
　(b) **清单申报不实**：候选清单 `durationFilter` 照抄请求参数申报 hard，与池内实况矛盾——申报层与执行层脱节（同族案=connector v0.13.1 申报歪形）；
　(c) **shortfall 标注只在兜底路径**：`durationShortfall` 标记仅在 soft-fallback 轮生成（`shortfall_floor` 只在 collect 兜底调用传入），hard 轮短轨无标记，卡片层失去"短于目标"的机器提示；
　(d) **登记件无时长字段**：合同 ⑫ 说"用登记件里 trackDurationMs 机器比对 G0 目标下限"，但 `music_register_candidate.py` 登记件不产任何时长字段（decodeProbe 同跑已握 ffprobe 时长而未取）——编排比对只能借分析报告/池 probe 数字，合同字段缺机械来源；
　(e) **`--tags` AND 语义零命中无提示**：`--tags happy,upbeat,cartoon` 三轮里两轮 0 candidates 0 excluded（status 仍 completed），检索饿死与标签合取过严不分｜期望：时长过滤真实生效或如实申报未生效；短轨一律带 shortfall 标记；登记件带 trackDurationMs；零命中给出放宽建议；实际：以上全部缺席，bgm-choice 前编排人工时长比对成为唯一防线｜**中（供给合同层，四处独立缺陷同编号归案）**｜11-19 G1 找乐六轮检索实录（候选清单 11 份在案：130928/131018/131246/131915/131939/132001/132232/132249/132910/133112/133116）
